PROJECT NAME:
Horizon

PROJECT TITLE:
Horizon – Weather-Aware Maritime Route Optimization System

PROJECT PURPOSE:
Horizon is a maritime voyage planning and route optimization platform. It should help a ship operator plan a route between two ports while considering marine weather conditions, maritime constraints, distance, estimated fuel consumption, travel time, CO₂ emissions, and safety.

The system should compare a normal/shortest maritime route with a weather-aware optimized route and visualize both on an interactive map.

The project must be realistic enough for a final-year engineering demonstration but should remain practical to build and run locally.

G. MARITIME ROUTE GENERATION

THIS IS VERY IMPORTANT.

Do NOT calculate maritime routes as a simple straight line through land.

Create a maritime navigation grid or graph.

Prevent routes from crossing obvious land areas.

and

Use Haversine distance for geographical distance calculations.

--------------------------------------------------
H. WEATHER-AWARE ROUTE OPTIMIZATION

This is the main feature of Horizon.

For each graph edge/node calculate a cost.

Conceptually:

Total Cost =
w1 × Distance Cost
+ w2 × Weather Risk
+ w3 × Fuel Cost
+ w4 × Time Cost
+ w5 × Safety Penalty

Normalize individual cost components before combining them where necessary.

Weather risk should consider:

- wave height
- wind speed
- current
- vessel safety thresholds

Example concept:

weatherRisk =
waveRisk +
windRisk +
currentRisk

If:

wave_height > vessel.max_wave_height

or

wind_speed > vessel.max_wind_speed

then the node/edge should receive a very large safety penalty or become non-navigable.

The optimized route should therefore be capable of going around dangerous weather rather than simply selecting the geometrically shortest path.

Create configurable weights.

Example:

Balanced:
distance = 0.30
weather = 0.30
fuel = 0.20
time = 0.10
safety = 0.10

These weights are examples.
Design them so they can be adjusted.
